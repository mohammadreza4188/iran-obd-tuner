# شواهد میدانی (Field Evidence Bundles)

این پوشه بسته‌های شواهد میدانی **بازبینی‌شده** را نگه می‌دارد: فایل‌های JSON که روی یک خودروی واقعی
با آداپتور فقط‌خواندنی ضبط شده‌اند (پروتکل گزارش‌شده آداپتور، PIDهای پشتیبانی‌شده، DIDهای شناسایی
UDS و بخشی از ترافیک خام). فعلاً هیچ بسته‌ای در اینجا نیست، پس هیچ ادعایی در پایگاه دانش `verified` نیست.

## چرا

یک ادعا در `src/iran_obd_tuner/database/data/vehicles/*.json` فقط وقتی می‌تواند `verified` شود که به
یک فایل در همین پوشه ارجاع دهد:

```json
"obd_physical_layer": {
  "value": "iso_15765_4_can_11_500",
  "confidence": "verified",
  "source": "src.field_pars_tu5_1400_a",
  "evidence": {"bundle": "evidence/feb-20270101T120000Z-1a2b3c4d.json", "sha256": "<content_sha256>"}
}
```

تست `tests/unit/test_vehicle_database.py` برای هر ادعای `verified` این را بررسی می‌کند:

- فایل وجود دارد و `content_sha256` آن با محتوا و با ارجاع ادعا یکی است (فایل دست‌کاری نشده)؛
- بسته شبیه‌سازی‌شده نیست (`simulated: false`، `usable_for_verification: true`)؛
- مقدار ادعا واقعاً در بسته مشاهده شده است (پروتکل، سرعت CAN، شناسه‌های درخواست/پاسخ، PIDها،
  DIDها، الگوهای F187/F189/F197). برای ادعاهایی که از ترافیک قابل بررسی نیستند (مثلاً خانواده ECU
  از روی برچسب)، `notes` ادعا باید توضیح دهد که شاهد چیست.

## گردش کار

1. با آداپتور فقط‌خواندنی روی خودرو (سوئیچ باز، موتور خاموش): `iran-obd-tuner diagnose --adapter elm327 --port <PORT>`
   و در صورت CAN بودن درگاه، `iran-obd-tuner uds-ident --interface <IF> --channel <CH>`، یا همین کارها در داشبورد.
2. تب «پایگاه دانش خودرو» ← خودرو و سال مدل را انتخاب کنید ← «ذخیره بسته شواهد…».
   گزینه پنهان کردن ۶ نویسه آخر VIN روشن بماند.
3. فایل را بازبینی کنید (فقط VIN پنهان می‌شود)، در این پوشه بگذارید و در Pull Request جداگانه همراه
   ویرایش بسته JSON خودرو ثبت کنید.

بسته‌های شبیه‌سازی‌شده (`simulated: true`) برای تمرین گردش کار مفیدند ولی **هرگز** نباید اینجا ثبت شوند.
