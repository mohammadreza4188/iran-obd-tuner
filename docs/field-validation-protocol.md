# پروتکل اعتبارسنجی میدانی (Field Validation Protocol)

این سند روش **اولین اتصال** نرم‌افزار به یک آداپتور ELM327 واقعی و سپس به یک خودروی واقعی است
(هدف اول: پژو پارس TU5، حدود ۱۴۰۰). هدف فقط **مشاهده و ثبت** است: هیچ نوشتن، پاک کردن کد خطا یا
تست عملگری انجام نمی‌شود و نرم‌افزار هم چنین قابلیتی ندارد (`docs/architecture.md`، بخش ۵).

نتیجه موفق این پروتکل یک **بسته شواهد میدانی** (Field Evidence Bundle) است که پس از بازبینی، تنها راه
ارتقای یک ادعا در پایگاه دانش خودرو از `unknown` به `verified` است (`evidence/README.md`).

> **قاعده طلایی:** هر جا چیزی غیرعادی دیدید — صدا، بو، گرما، چراغ هشدار، پیام خطای ناآشنا — **توقف کنید**،
> سوئیچ را ببندید و آداپتور را جدا کنید. ادامه دادن هیچ‌وقت از توقف ارزشمندتر نیست.

## ۰. دامنه و ممنوعات این مرحله

- فقط **آداپتور ELM327** (ترجیحاً USB؛ بلوتوث فقط اگر USB در دسترس نیست).
- **ممنوع در این مرحله:**
  - `uds-ident` روی رابط CAN واقعی (`slcan`/`pcan`/`kvaser`) و پنل UDS با رابط واقعی — تا یک
    اعتبارسنجی جداگانه روی میز کار CAN انجام شود؛
  - `--extended-session` و چک‌باکس جلسه Extended؛
  - هر نرم‌افزار دیگر (مثل برنامه‌های موبایل) در همان جلسه، به‌ویژه برنامه‌هایی که «پاک کردن کد خطا» دارند؛
  - به‌روزرسانی یا فلش کردن firmware آداپتور؛
  - جدا کردن باتری خودرو یا روشن کردن موتور در طول جلسه.

## ۱. پیش‌نیازها

- [ ] کد از یک commit مشخص روی `main` اجرا می‌شود و `python scripts/check.py` همان روز سبز بوده است.
      شماره commit و خروجی `iran-obd-tuner version` را در برگه ثبت (بخش ۷) بنویسید.
- [ ] `[obd]` نصب است (`python -m pip install -e ".[obd]"` یا `[full]`).
- [ ] لپ‌تاپ با **باتری** کار می‌کند (به اینورتر یا شارژر داخل خودرو وصل نیست).
- [ ] یک پوشه خروجی، مثلاً `field/` (این پوشه را commit نکنید؛ VIN کامل در آن هست).
- [ ] ثبت لاگ در فایل فعال است:

```powershell
$env:IRAN_OBD_TUNER_LOG_FILE = "field\session.log"
```

## ۲. بررسی آداپتور روی میز کار (پیش از نزدیک شدن به خودرو)

هدف: مطمئن شویم آداپتور (به‌ویژه کلون‌های ارزان) اتصال کوتاه ندارد و همان دستگاهی است که فکر می‌کنیم.

1. **بازرسی ظاهری:** بدنه سالم، پین‌های کانکتور OBD صاف و تمیز، بدون بوی سوختگی یا قطعه بادکرده.
2. **مولتی‌متر (آداپتور بی‌برق):** نقشه پین‌ها: ۴ = بدنه، ۵ = زمین سیگنال، ۱۶ = مثبت باتری، ۶/۱۴ =
   CAN-H/CAN-L، ۷ = خط K.
   - بین ۱۶ و ۴، و بین ۱۶ و ۵ **نباید** مقاومت نزدیک صفر باشد. اگر کمتر از چند اهم بود، آداپتور را کنار بگذارید.
   - بین ۶ و ۱۴، و بین ۷ و ۴/۵ هم نباید اتصال کوتاه (حدود ۰ اهم) باشد.
3. **برق‌دار کردن با منبع تغذیه محدودشده:** ۱۲ ولت روی پین ۱۶ و زمین روی ۴/۵، با محدودیت جریان
   حدود ۲۰۰ میلی‌آمپر. اگر جریان به سقف رسید، یا پس از چند دقیقه قطعه‌ای داغ شد، آداپتور رد است.
4. **USB و درگاه:** آداپتور را به لپ‌تاپ وصل کنید و درگاه COM آن را در Device Manager پیدا کنید.
   در داشبورد هم دکمه تازه‌سازی درگاه‌ها آن را نشان می‌دهد. سپس:

```powershell
iran-obd-tuner adapters
```

   ردیف `elm327` باید `implemented` باشد و ردیف `mock` با برچسب شبیه‌سازی‌شده.

5. **آزمون خشک (آداپتور فقط روی منبع تغذیه، بدون خودرو):**

```powershell
iran-obd-tuner --log-level DEBUG diagnose --adapter elm327 --port COM5 --no-live
```

   به‌جای `COM5` درگاه خودتان را بنویسید. نتیجه مورد انتظار:
   - در لاگ: پاسخ `ATZ` با شناسه‌ای مثل `ELM327 v1.5`. این رشته را ثبت کنید.
   - پس از جستجوی پروتکل (تا حدود ۳۰ ثانیه)، خطای صریح مثل `UNABLE TO CONNECT - is the ignition on?`.
   - در آخر لاگ `AT PC` و بسته شدن درگاه. برنامه نباید گیر کند.
   - اگر خطای `did not identify as an ELM327` آمد: دستگاه روی آن درگاه ELM327 نیست. هیچ فرمان دیگری
     فرستاده نشده است. درگاه را بررسی کنید.

## ۳. وضعیت اجباری خودرو

| مورد | وضعیت لازم |
|---|---|
| سوئیچ | **باز (ON / وضعیت II)** |
| موتور | **خاموش** — در کل جلسه روشن نمی‌شود |
| ترمز دستی | **کشیده** |
| دنده | خلاص (N) |
| خودرو | **کاملاً متوقف**، روی سطح صاف، بیرون از مسیر عبور |
| مصرف‌کننده‌ها | چراغ، بخاری/کولر، فن و ضبط خاموش |
| باتری | ولتاژ را پیش از شروع با مولتی‌متر بخوانید و ثبت کنید. زیر حدود ۱۲٫۲ ولت شروع نکنید |
| زمان | کل جلسه با سوئیچ باز حداکثر حدود ۲۰ دقیقه، برای خالی نشدن باتری |

## ۴. ترتیب اجرا روی خودرو

1. **اتصال فیزیکی با سوئیچ بسته:** آداپتور را به سوکت OBD وصل کنید، بعد سوئیچ را باز کنید. موتور
   روشن نشود. ده ثانیه صبر کنید.
2. **گزارش «پیش از جلسه» با کمترین ترافیک:**

```powershell
iran-obd-tuner --log-level DEBUG diagnose --adapter elm327 --port COM5 --no-live --json --output field\before.json
```

   این دستور فقط شناسایی، PIDهای پشتیبانی‌شده (bitmaskها)، PID `0101`، کدهای خطای ذخیره/معلق/دائمی
   و Freeze Frame 00 را می‌خواند و هیچ Live Data نمی‌خواند. ثبت کنید:
   - پروتکل گزارش‌شده (`AT DPN`)؛
   - تعداد PIDهای پشتیبانی‌شده؛
   - کدهای خطای موجود (فقط ثبت، **هیچ اقدامی برای پاک کردن**).
3. **Live Data کوتاه در داشبورد:**

```powershell
iran-obd-tuner-gui
```

   حالت «آداپتور واقعی» را انتخاب کنید، درگاه را انتخاب و وصل شوید. یک تا دو دقیقه مقادیر را ببینید:
   - دور موتور باید صفر یا «بدون پاسخ» باشد (موتور خاموش است). هر مقدار عجیب را ثبت کنید.
   - اگر پیام «سوئیچ بسته شد؟» آمد، یعنی سه poll پیاپی بی‌پاسخ ماندند و اتصال خودکار قطع شد. وضعیت
     سوئیچ و آداپتور را بررسی کنید.
4. **خروجی بسته شواهد (در همان جلسه داشبورد):** تب «پایگاه دانش خودرو» ← خودرو و سال مدل را انتخاب کنید
   ← «ذخیره بسته شواهد…». گزینه پنهان کردن ۶ نویسه آخر VIN **روشن بماند**. فایل را در `field\` ذخیره کنید.
5. **قطع در داشبورد:** دکمه قطع اتصال (در این لحظه `AT PC` فرستاده می‌شود). داشبورد را ببندید.
6. **گزارش «پس از جلسه»:**

```powershell
iran-obd-tuner diagnose --adapter elm327 --port COM5 --no-live --json --output field\after.json
```

7. **پایان:** سوئیچ را ببندید، **بعد** آداپتور را از سوکت جدا کنید. کلون‌ها از سوکت برق می‌گیرند و
   خاموش نمی‌شوند. ولتاژ باتری را دوباره ثبت کنید.

### معیارهای توقف فوری

جلسه را متوقف کنید (سوئیچ بسته، آداپتور جدا) اگر:

- چراغ هشداری روی آمپر روشن شد یا رفتارش عوض شد، یا رله/فن/پمپ بی‌دلیل صدا داد؛
- خطاهای `BUS BUSY`، `CAN ERROR`، `BUS ERROR`، `FB ERROR` یا `LV RESET` آمد (برنامه خودش هم قطع می‌کند)؛
- آداپتور داغ شد یا بو داد؛
- دو بار پیاپی اتصال شکست خورد (بار سوم امتحان نکنید؛ ابتدا علت را روی میز کار پیدا کنید)؛
- ولتاژ باتری زیر حدود ۱۲ ولت رفت.

## ۵. پس از جلسه: مقایسه و بازبینی

1. **مقایسه `before.json` و `after.json`:** کدهای خطا (به‌ویژه کدهای `U` شبکه) باید یکسان باشند. کد
   جدید یعنی ممکن است جلسه باس را مختل کرده باشد. در این حالت **هیچ ادعایی را ارتقا ندهید**، موضوع را
   با لاگ و بسته گزارش کنید و تا روشن شدن علت جلسه دیگری برگزار نکنید.
2. **بازبینی بسته:** باید `simulated: false` و `usable_for_verification: true` باشد. VIN فقط با ۶ نویسه آخر
   پنهان‌شده دیده شود. بقیه محتوا را هم برای اطلاعات شخصی بخوانید (فقط VIN خودکار پنهان می‌شود).
3. فایل‌های `before.json`، `after.json` و لاگ VIN کامل دارند: آن‌ها را **منتشر یا commit نکنید**.

## ۶. ارتقای ادعا از `unknown` به `verified`

ارتقا یک ویرایش بازبینی‌شده است و خودکار انجام نمی‌شود.

1. بسته بازبینی‌شده را با همان نام فایل در پوشه `evidence/` بگذارید.
2. در بسته JSON خودرو (`src/iran_obd_tuner/database/data/vehicles/*.json`):
   - یک منبع با `"kind": "field_evidence"` به فهرست `sources` اضافه کنید؛
   - فقط ادعاهایی را که **واقعاً در بسته دیده شده‌اند** (مثل پروتکل، بیت‌ریت CAN، PIDهای پشتیبانی‌شده)
     به `"confidence": "verified"` تغییر دهید و ارجاع شواهد را بنویسید:
     `"evidence": {"bundle": "evidence/<file>.json", "sha256": "<content_sha256>"}`.
   - ادعاهایی که از ترافیک قابل دیدن نیستند (مثل خانواده ECU از روی برچسب) باید در `notes` توضیح
     دهند شاهدشان چیست، مثلاً عکس برچسب. حدس هیچ‌وقت `verified` نمی‌شود.
3. اجرا:

```powershell
python -m pytest -q tests/unit/test_vehicle_database.py
```

   این تست بررسی می‌کند که هش درست است، بسته شبیه‌سازی‌شده نیست و مقدار ادعا در بسته دیده شده است.
4. برای این تغییر یک Pull Request **جداگانه** باز کنید: بسته، ویرایش JSON و برگه ثبت (بخش ۷).
5. بسته شبیه‌سازی‌شده (`simulated: true`) **هرگز** در `evidence/` قرار نمی‌گیرد.
