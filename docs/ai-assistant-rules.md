سند مرجع طراحی: [`architecture.md`](architecture.md).

## پروژه در یک پاراگراف

`iran-obd-tuner` ابزار پایتونی تشخیص OBD-II و در فازهای بعدی تیونینگ Bench برای بازار ایران
است. امروز یک اسکلت حرفه‌ای، یک جریان تشخیصی **فقط‌خواندنی** کاملاً مستقل از سخت‌افزار (آداپتور
شبیه‌ساز) و یک داشبورد PySide6 (فاز ۱) روی همان داده شبیه‌سازی‌شده وجود دارد. **آداپتور واقعی
پیاده نشده و هیچ مسیر نوشتن روی ECU فعال نیست** — پاک کردن کدها در داشبورد عمداً توسط گارد
ایمنی رد می‌شود و فقط پیام «غیرفعال» نشان می‌دهد.

## قواعد الزامی

1. **هرگز کدی که روی خودرو می‌نویسد اضافه نکنید.** پاک کردن DTC، تست عملگر، فلش ECU، نوشتن
   کالیبراسیون، دور زدن Security Access و فرمان‌های مخرب ممنوع است. هر نقطه ورودی تغییردهنده
   وضعیت باید از `core.safety.require(...)` یا `tuning.interfaces.assert_write_allowed(...)`
   عبور کند.
2. **هرگز در تست، CI، زمان import یا setup فرمانی به خودرو ارسال نکنید.** تست‌ها فقط با
   `MockObdAdapter` و `MockScenario` (و `FailureMode` برای خطاهای ارتباطی) کار می‌کنند.
3. **هرگز اجازه ندهید تنظیمات، نوشتن را فعال کند.** `SafetyPolicy` فقط در کد ساخته می‌شود، نه
   از TOML و نه از متغیر محیطی.
4. **چیزی از خود نسازید.** پروتکل، PID، توضیح کد خطا، توانایی سخت‌افزار و نتیجه تست باید قابل
   استناد باشند. اگر بررسی نشده، بنویسید «بررسی نشده»؛ اگر پیاده نشده، همان را اعلام کنید
   (الگو: `hardware/registry.py`). هیچ نتیجه تست/دستور/سخت‌افزاری را که اجرا نکرده‌اید گزارش نکنید.
5. **مرزهای لایه‌ها:** `core` فقط کتابخانه استاندارد؛ `hardware` نباید `diagnostics`/`database`
   را import کند؛ `database` نباید `hardware`/`diagnostics` را import کند؛ انتخاب پیاده‌سازی
   مشخص فقط در `app`. import کتابخانه خارجی فقط داخل ماژول همان آداپتور/رابط، نه در `__init__` بسته‌ها.
6. **وابستگی جدید:** دلیل در متن PR + قرار گرفتن در extra مناسب `pyproject.toml`. هسته باید با
   کتابخانه استاندارد به‌تنهایی اجرا شود.
7. **زبان:** کد (شناسه، docstring، کامنت) انگلیسی؛ `README.md`، `docs/*` و `CONTRIBUTING.md` فارسی.
8. **کامیت نکنید:** `output/`، لاگ‌ها، `config/local.toml`، `*.bin`، `*.hex`، `*.rom`، رمزها و
   محیط مجازی. (کامیت/پوش/مِرج/ریف‌ریش تاریخچه فقط با درخواست صریح کاربر.)

## پیش از پایان هر تغییر

```bash
python scripts/check.py          # compile + ruff check + ruff format --check + pytest
```

به‌صورت جداگانه:

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
```

همه تست‌ها باید بدون سخت‌افزار و بدون شبکه پاس شوند.

## کجا چه چیزی قرار می‌گیرد

| موضوع | مسیر |
|---|---|
| تنظیمات، لاگ، مدل‌ها، کاتالوگ PID/DTC، سیاست ایمنی | `src/iran_obd_tuner/core/` |
| قرارداد آداپتور، شبیه‌ساز، رجیستری | `src/iran_obd_tuner/hardware/` |
| جریان تشخیص، مدل گزارش و سرویس داشبورد | `src/iran_obd_tuner/diagnostics/` |
| دسترسی به داده دانش (و داده JSON همراه) | `src/iran_obd_tuner/database/` |
| رابط‌های Bench و پیش‌نیاز نوشتن | `src/iran_obd_tuner/tuning/` |
| داشبورد PySide6 (ویجت‌ها، رشته‌ها، پنجره اصلی) | `src/iran_obd_tuner/ui/` |
| CLI، ورودی GUI و سیم‌کشی | `src/iran_obd_tuner/app/` |
| تست واحد / انتها-به-انتها (CLI و GUI) / داده نمونه | `tests/unit/`, `tests/integration/`, `tests/fixtures/` |

## قراردادهای کد

- `from __future__ import annotations` در همه ماژول‌ها؛ type annotation کامل.
- `@dataclass(frozen=True, slots=True)` برای مدل‌ها، اعتبارسنجی در `__post_init__`.
- خطاها از `iran_obd_tuner.core.exceptions`؛ بدون `except` لخت.
- لاگ با `core.logging.get_logger`؛ `print` در کد کتابخانه‌ای ممنوع.
- طول خط ۱۰۰؛ ruff تنها ابزار لینت/فرمت.
- هر ماژول در docstring بگوید چه چیزی پیاده و چه چیزی پیاده **نشده** است.
